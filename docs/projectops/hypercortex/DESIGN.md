# DESIGN

## [ALTERNATIVES_CONSIDERED]

### 대안 A: 벤치마크 루프 중간에 자바스크립트가 직접 Ollama Unload API를 병렬 호출하는 방식
- **장점**: 백엔드에 추가적인 Unload API를 구현할 필요가 없고 클라이언트 단독으로 루프를 돌며 API를 날림.
- **단점**:
  - `apiFetch`를 통해 브라우저가 포트 `11434`에 Nginx 우회로 직접 Unload 하도록 짜려면 CORS(Cross-Origin Resource Sharing) 충돌이 유발되거나 API-KEY 보존 규약을 통과하기가 매우 복잡해집니다.
  - 백그라운드 스레드에서 돌아가는 벤치마크의 트랙 상태와 GPU 스왑 시점이 미스매치되어 불안정성이 증가합니다.

### 대안 B: [선택안] 백엔드 주도형 VRAM Unload + 윈도우 서비스 관리판 개설 (Stateful Clean-VRAM)
- **장점**:
  1. **매 모델 추론 즉시 백엔드 강제 Unload**: Flask `/ollama/chat` 라우터가 모델 인퍼런스를 끝내자마자, 해당 성공/실패 데이터를 DB에 기록한 뒤 즉각 Ollama 로컬 데몬에 `keep_alive: 0`을 포함한 임시 해제 신호를 밀어 넣어 VRAM을 항상 깨끗한 도화지 상태로 즉각 순화합니다.
  2. **독립된 "Ollama 제어" 어드민 탭 구현**: 팰월드와 동일한 세련된 모니터링 컨트롤판을 웹 페이지에 탑재하여, VRAM 점유 모델 목록을 실시간 추적하고 외부망에서도 원클릭으로 데몬 프로세스 리부트 및 윈도우 Logs 실시간 스트리밍 뷰잉을 무결 지원합니다.
  3. **권한 폴백(NSSM & Taskkill) 가드 탑재**: 서비스 관리자 권한 거부 시, 일반 USER 권한으로도 기동 가능한 강제 태스크 킬 및 백그라운드 재실행 폴백 구조를 지녀 윈도우 OS 상에서 에러 없이 소생함을 보증합니다.
- **단점**: 백엔드에 윈도우 프로세스/로그 추적 헬퍼 및 신규 UI 탭 추가를 위한 마크업 및 JS 작성이 가미되어야 합니다.

## [SOLUTION]

### 1. Ollama 전용 관리 대시보드 UI/UX 설계 (`ollama.html` / `audit.js` 연계)
- **탭 개설**: 왼쪽 네비게이션 탭 메뉴에 "Ollama 관리"를 전격 신설하고, 팰월드 스타일의 미려하고 반응성이 뛰어난 카드 3개를 배치합니다.
- **카드 1: 데몬 제어 및 프로세스 상태**:
  - 구동 상태 지시등(그린: 구동중, 레드: 정지/크래시)
  - 'Ollama 시작', 'Ollama 중지', 'Ollama 재시작' 관리자 조작 버튼 탑재
- **카드 2: VRAM 점유 모니터링 및 강제 청소**:
  - 현재 VRAM에 로드되어 GPU 메모리를 잠식 중인 모델명 목록 실시간 가시화
  - "VRAM 강제 청소 (Unload)" 버튼을 부착하여 메모리 즉시 반환 유발
- **카드 3: Ollama 실시간 로그 뷰어**:
  - 윈도우 서버 내의 `server.log` 최근 200줄을 실시간 페이징 로드하는 스트리밍 뷰어 배치

### 2. 백엔드 시스템 제어 및 자동 탐색 설계 (`ollama_service.py`)
- **윈도우 서비스/데몬 관리 폴백 아키텍처**:
  - `Restart-Service -Name Ollama` 를 우선 시도하고, 권한 오류 발생 시 `taskkill /F /IM ollama.exe` 를 호출한 뒤 `subprocess.Popen` 기법으로 백그라운드 오프라인 데몬 프로세스(`ollama app` 혹은 `ollama serve`)를 안전하게 직렬 리부트합니다.
- **VRAM 점유 조회 및 강제 언로드 로직**:
  - 로컬 Ollama API인 `GET http://127.0.0.1:11434/api/ps`를 백엔드에서 주기적으로 호출하여 현재 VRAM 모델 목록 정보를 프론트에 반환합니다.
  - 언로드 호출 시, 대상 모델을 향해 `POST /api/chat` 에 `{"model": "모델명", "messages": [], "keep_alive": 0}` 인자를 담아 쏘아 보내어 메모리에서 영구히 강제 반환시킵니다.
- **Ollama 윈도우 로그 자동 바인더**:
  - 윈도우 OS의 특성을 고려하여, 사용자 홈 디렉토리 명세를 런타임에 동적으로 추출한 뒤, `~/.ollama/logs/server.log` 및 `AppData/Local/Ollama/server.log` 등의 후보 경로를 스캔하여 실제 유효하게 존재하는 로그 파일의 절대경로를 자동 격리 바인딩합니다.

### 3. 벤치마크 테스트와 연동 최적화 (`ollama-test.html` / `ollama-test.js`)
- 테스트 요청 구성 카드 상단에 **"자동 VRAM 청소 정책 (Auto Unload)" 토글 스위치(기본값: ON)**를 전격 배치합니다.
- 활성화되어 구동될 경우, 자바스크립트가 개별 모델 실행 직전/직후에 백엔드로 `POST /ollama/control/unload` 신호를 쏘아 보내어, VRAM 적재 한계를 항시 `0GB`에 가깝게 유지해 대형 모델 테스트를 무제한으로 돌려도 절대 지연되거나 타임아웃 나지 않는 완벽한 기어 장치를 수립합니다.

## [REVIEW_LOG]
* **검토자**: Reviewer Persona
* **검토 의견**:
  - **보안 가드**: `taskkill` 이나 윈도우 CMD/파워쉘 명령어를 `subprocess.run` 또는 `Popen`을 통해 백엔드에서 실행하는 행위는 Command Injection 취약점에 극도로 정교하게 대비해야 합니다. 따라서 사용자가 파라미터(예: `model_name` 이나 `action` 등)를 주입할 때 쉘 보간 메타 문자(`&`, `|`, `;`, `$`, `` ` `` 등)가 절대 침투하지 못하도록 정규식 필터링을 완벽하게 걸거나, 쉘 기동을 아예 사용하지 않는 `shell=False` 및 단독 아규먼트 배열 맵 기법(`["taskkill", "/F", "/IM", "ollama.exe"]`)을 의무적으로 사용해야 합니다.
  - **예외 복원력**: Ollama 서버가 아예 꺼져 있거나 기절한 상태에서는 `GET http://127.0.0.1:11434/api/ps` 호출이 커넥션 거부(`ConnectionRefusedError`)를 뿜을 것입니다. 이 예외를 백엔드 서비스 단에서 포착하여, 데몬이 정지 상태임을 사용자에게 친절히 알리고 소생 버튼을 누를 수 있도록 UI 가이드를 열어주어야 정성적으로 안전합니다.
