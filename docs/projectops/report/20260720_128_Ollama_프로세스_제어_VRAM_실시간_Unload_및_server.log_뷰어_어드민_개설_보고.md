# [기능추가] Ollama 프로세스 제어, VRAM 실시간 Unload(청소) 및 server.log 뷰어가 내장된 Ollama 관리 어드민 개설 보고 (#128)

## 개요
기존에 은닉되어 추적할 수 없었던 로컬 Ollama 데몬의 생사 및 VRAM 모델 점유 정보를 원격 브라우저 단에서 즉각 감지하고 제어할 수 있도록, 팰월드 스타일의 독립 전용 "Ollama 관리" 대시보드 탭 개설 및 2중 복원력 파워쉘/Taskkill 래퍼, 자동 로그 수집기 연계를 완료하였습니다.

---

## 세부 구현 및 이식 내역

### 1. Ollama 관리 전용 독립 웹 탭 개설 (`/admin/ollama`)
- 왼쪽 네비게이션 탭 메뉴에 `Ollama 관리`를 신설하고 동적 렌더링 라우팅을 확보하였습니다.
- **데몬 제어**: 현재 구동 여부 상태 실시간 지시등(그린: 구동중, 레드: 정지) 및 시작/중지/재시작 제어판 탑재
- **VRAM 점유 제어**: 현재 VRAM에 적재되어 GPU 메모리를 좀먹는 모델 목록 실시간 PS 표출 및 개별/일괄 언로드 메모리 반환 조작 연계
- **로그 스트리밍**: 윈도우 `server.log` 의 최근 200줄 데이터 뷰어 개설 (에러 라인 필터링 표시)

### 2. 윈도우즈 서비스 권한 극복 2중 명령 래퍼 및 로그 자동 바인딩
- **2중 복원력 데몬 시작/재시작**: `Restart-Service -Name Ollama` 실패 시 일반 사용자 권한에서도 정상 기동되는 강제 좀비 소멸 태스크킬(`taskkill /F /IM ollama.exe`) 및 콘솔 창 노출 없이 백그라운드 구동을 보증하는 `subprocess.Popen(["ollama", "serve"])` 오프라인 백그라운드 구동 래퍼 이식 완료
- **로그 자동 추적 및 인코딩 가드**: 사용자 홈 디렉토리를 런타임 동적 스캔하여 logs 후보 세 곳 중 유효한 `server.log` 경로를 자동 탐색 바인딩하고, 로그를 읽어올 때 `open(path, errors='ignore', encoding='utf-8')` 가드를 엄격히 가미하여 윈도우 한글 인코딩 크래시 원천 차단 완결
