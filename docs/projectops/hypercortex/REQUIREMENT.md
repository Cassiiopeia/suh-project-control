# REQUIREMENT

## [PROBLEM]
현재 제공되는 Ollama Structured Output 테스트 페이지(`ollama-test.html`, `ollama-test.js`)는 다중 모델 순차 테스트 및 지표 분석 테이블까지 성공적으로 구축되었으나, 다음과 같은 두 가지 핵심 한계가 남아 있습니다.
1. **결과 데이터의 휘발성**: 테스트 결과가 오직 브라우저 메모리에만 상주하므로, 페이지를 새로고침하거나 탭을 닫으면 과거 실행했던 소중한 벤치마킹 데이터와 생성된 고품질 JSON 결과물이 고스란히 유실됩니다.
2. **실패 모델 재실행의 높은 비용**: 20~30개의 모델을 대상으로 테스트를 수행하는 과정에서 특정 모델이 일시적인 OOM, 타임아웃, 혹은 네트워크 순간 단절로 인해 `실패` 상태가 되었을 때, 오직 그 실패한 모델만 선별하여 다시 테스트할 수 있는 방안이 부재합니다. 이로 인해 전체 모델을 처음부터 다시 실행해야 하는 엄청난 시간 및 컴퓨팅 자원 낭비가 초래됩니다.

## [REQUIREMENT]

### 1. 관계형 데이터베이스(RDB) 기반 영구 보존 체계 구축 (마이그레이션 0003)
- **마스터 테이블 (`benchmark_batch`)**: 배치 단위의 실험 환경(프롬프트 원문, 시스템 프롬프트, 샘플링 온도, 포맷 모드, JSON Schema 사양, 생성 시각)을 영구 보존합니다.
- **세부 결과 테이블 (`benchmark_result`)**: 각 모델별 정량/정성 성능 지표(성공여부, 응답 JSON 원문/에러 로그, 총 지연, 로딩 지연, 추론 지연, 인풋/아웃풋 토큰, 초당 토큰 속도, 스키마 준수성)를 보존합니다.
- **정합성 보증 (UPSERT)**: 동일 모델의 중복 레코드 삽입 방지를 위해 `(batch_id, model_name)`에 복합 유니크 제약을 설정하고, 재시도 시 기존 레코드가 정확히 업데이트되도록 `ON CONFLICT DO UPDATE` 구조를 강제합니다.

### 2. 백엔드 REST API 설계 및 구현 (Flask)
- `POST /ollama/benchmark/batch`: 벤치마크 시작 시 마스터 세션을 생성하고, 발급된 고유 `batch_id`를 반환합니다.
- `POST /ollama/benchmark/result`: 각 모델의 실행이 끝날 때마다 결과 데이터를 실시간 전송받아 UPSERT 합니다. (중도 중단 시에도 보존 가능)
- `GET /ollama/benchmark/history`: 과거 벤치마크 테스트 이력 목록(최근 15개)을 페이징 혹은 역순으로 조회합니다.
- `GET /ollama/benchmark/history/<batch_id>`: 특정 배치 마스터에 귀속된 상세 모델 성능 지표 및 원문 JSON 목록을 조회합니다.

### 3. 프론트엔드 실패 모델 재실행 (Retry) 기능 탑재
- **전체 재실행**: 배치 카드 상단에 "실패 모델만 일괄 재실행" 버튼을 노출하여, 상태가 `fail`인 모든 모델에 대해 단 한 번의 클릭으로 재시험을 가동합니다.
- **개별 재실행**: 요약 비교 테이블 내의 `실패` 배지 우측에 새로고침 아이콘 형태의 작은 재시도 버튼을 배치하여, 특정 모델 단 한 개만 기민하게 개별 재테스트할 수 있는 극상의 UX를 제공합니다.
- **데이터 실시간 갱신**: 재시험 성공 시, 요약 테이블 및 상세 카드가 동적으로 갱신되며 백엔드에 결과를 즉각 업데이트(`UPSERT`)합니다.

### 4. 과거 벤치마크 이력 조회 대시보드 및 복원 탭 추가
- 'Ollama 테스트' 페이지 하단 영역에 **"과거 테스트 이력 조회"** 카드를 추가합니다.
- 데이터베이스로부터 최근 배치 이력들을 아코디언 목록으로 동적 바인딩합니다.
- 아코디언 헤더를 펼치면, **과거 저장되었던 요약 지표 테이블과 개별 상세 JSON 카드가 화면에 당시 구조 그대로 복원 및 시각화**됩니다.
- 과거 이력에 실패한 모델이 존재할 경우, 해당 카드 위에서도 **즉석으로 재실행을 기동하여 성공 결과로 이력을 최종 업데이트**할 수 있습니다.
- "이 설정으로 다시 테스트" 버튼을 제공하여, 과거 시점의 프롬프트와 JSON Schema를 에디터로 로딩 복원해 즉각적인 후속 실험을 지원합니다.

## [REVIEW_LOG]
* **검토자**: Reviewer Persona
* **검토 의견**:
  - **Critical Edge Case 1 (과거 이력의 스키마 정합성)**: 사용자가 과거 이력 아코디언을 펼쳤을 때 복원되는 테이블에서 "재시도"를 실행할 경우, 현재 활성화되어 입력창에 있는 프롬프트와 스키마가 아닌, **당시 배치 세션에 영구 보존되어 있던 프롬프트와 스키마 정의를 추출하여 재시도 요청을 보내야** 합니다. 그렇지 않으면 과거 결과가 엉뚱한 현재 입력창 내용으로 오염되어 정합성이 완전히 붕괴됩니다. 설계 시 이 Context Binding을 완벽하게 수립해야 합니다.
  - **UX 피드백 (과거 이력 로드 시점)**: 페이지 진입 시 과거 이력 목록 전체를 한꺼번에 읽어오는 것은 속도 지연을 유발할 수 있습니다. 마스터 리스트만 가볍게 렌더링하고, 사용자가 특정 배치 아코디언을 **클릭하여 펼치는 순간(On Expand)** 백엔드에서 세부 모델 결과들을 비동기로 지연 로딩(Lazy Loading)해 오도록 설계하면 초기 로딩 지연을 최소화할 수 있습니다.
