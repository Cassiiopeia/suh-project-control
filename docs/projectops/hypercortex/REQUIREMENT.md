# REQUIREMENT

## [PROBLEM]
현재 SUH AI Server의 모델 관리 페이지(`admin/models`)와 Ollama 테스트 페이지(`admin/ollama-test`)에서 모델을 다루는 데 다음과 같은 사용성 제약과 불편함이 존재합니다:
1. **HuggingFace 일괄 고립 분류**: 허깅페이스(`hf.co/`)에서 직접 다운로드한 모델들이 실제 설계 아키텍처(예: `gemma3`, `granite4` 등)와 관계없이 프론트 단에서 일률적으로 `HuggingFace`라는 단일 그룹으로 통합 분류되어 아키텍처 식별이 대단히 난해합니다.
2. **모델 관리 페이지 그룹화 부재**: Ollama 테스트 페이지와 달리, 모델 관리 페이지의 설치 모델 목록은 패밀리 단위 그룹화 없이 단일 평면 테이블로 나열되어 탐색 가독성이 저하됩니다.
3. **다차원 검색 및 정밀 필터링 결여**: 수십 개의 다양한 모델 중 파라미터 크기(b), 디스크 용량, 특성(Vision, Embedding 등), 다운로드 출처별로 탐색을 좁힐 수 있는 필터 컨트롤이 전혀 없어 테스트 선정과 모델 관리에 극심한 수동 인지 피로를 겪고 있습니다.
4. **API 문서 iframe 렌더링 실패 및 인증 모호성**: admin 레이아웃 안에 임베드된 API 문서 페이지(`/admin/api-docs`)에서 iframe이 로드되지 않고 빈 화면만 노출되는 결함이 있으며, Swagger UI 자체 및 API 호출 테스트 시 API Key(X-API-Key)의 정밀한 필요 여부가 불분명하여 개발자 인지 혼선이 발생하고 있습니다.

## [REQUIREMENT]

### 1. 양측 페이지의 아키텍처 패밀리 정렬 및 그룹화 통합
- **실제 패밀리 추출기 구현 (`getFamily`)**: 모델명에 `hf.co/` 경로가 포함되어 있더라도 해당 문자열을 파싱 및 정제하여 원천 아키텍처 계열(예: `gemma3`, `gemma3n`, `gemma4`, `deepseek-r1`, `granite4`, `ministral-3`, `qwen3`, `qwen3-vl`, `qwen3.5`, `hyperclovax`, `kanana` 등)로 완벽히 추출하고 매핑합니다.
- **그룹화 적용**: 이 분류 룰을 **모델 관리 페이지**와 **Ollama 테스트 페이지**에 동시에 탑재하여 동일한 아키텍처별로 묶어 정렬하고 표시합니다.

### 2. 다차원 정밀 필터 컨트롤 패널 탑재 (DaisyUI 완전 활용)
양측 페이지 상단에 세련된 DaisyUI 기반의 반응형 필터 제어 영역을 전격 개설합니다:
- **텍스트 검색 (Search)**: 모델명 및 패밀리명 대소문자 구분 없이 실시간 동적 검색
- **파라미터 크기 (Parameters)**: 전체 / `< 1B` (초경량) / `1B - 4B` / `4B - 8B` / `> 8B` (대형) 선택 드롭다운
- **파일 용량 범위 조절 (Stepped Range Slider)**: 드래그 핸들 방식의 슬라이더를 도입하여 선택한 상한 용량 이하의 모델만 실시간 필터링.
  - 단계 구성: `0.5GB 이하` ➡️ `1GB 이하` ➡️ `4GB 이하` ➡️ `8GB 이하` ➡️ `12GB 이하` ➡️ `16GB 이하` ➡️ `전체 (제한없음)`
- **모델 유형 (Capability)**: 전체 / `Vision/OCR` / `Embedding` / `General Text` 선택 드롭다운
- **출처 (Source)**: 전체 / `Ollama 공식 라이브러리` / `Hugging Face (GGUF)` 선택 드롭다운

### 3. 필터링 및 패밀리 분류 로직의 공통화 (Common JS Utility)
- 모델을 다루는 여러 화면(테스트, 관리 등)에서 일관된 모델 분류와 필터링 로직이 재사용되도록, 핵심 데이터 분석 및 필터 처리 함수를 공통 유틸리티화하여 설계합니다.

### 4. 체크박스 일괄 조작 보강 (Ollama 테스트 페이지)
- 현재 필터링되어 화면에 보이는 모델들에 대해서만 **"전체 선택"** 및 **"전체 해제"**가 안전 동작하도록 로직을 세분화하여 필터 가시성 편의를 제공합니다.

### 5. API 문서 iframe 렌더링 정상화 및 가이드 명확화
- **iframe 주소 구조적 보정**: 로컬과 배포 환경에 구애받지 않고 트레일링 슬래시 미비로 인한 하위 자산 404를 원천 예방하도록 `{{ root }}/api/flask/docs/swagger/` 의 물리 및 트레일링 경로를 완벽히 지정합니다.
- **X-API-Key 가이드 정리**: Swagger UI 문서 로드 자체는 public bypass 규칙에 의해 API Key가 무방하지만, 내부에서 "Try it out"을 실행하기 위해서는 브라우저 localStorage 등에 저장된 `X-API-Key` 값을 우측 상단 `Authorize` 버튼에 바인딩해야 함을 명확히 고지합니다.

## [ASSUMPTIONS]
- 설치 모델의 `parameter_size` 정보는 Ollama에서 `"1.5B"`, `"8B"`, `"270M"` 등 문자열로 들어옵니다. 파싱 함수를 추가해 단위(`B`=실수, `M`=`/1000`)를 정밀 변환하여 대소 판별을 처리합니다.
- `hf.co/` 모델의 이름은 `/`로 여러 번 나뉠 수 있으므로, 경로를 세그먼트별로 분할하여 가장 마지막에 위치하는 실제 모델명 파일의 키워드를 기준으로 패밀리를 자동 검출합니다.

## [AMBIGUITY]
- 모델 유형 판정 시, `vision` 모델은 DB 컬렉션의 `m.vision` 필드가 `true`이거나, 모델 이름 내에 `vision`, `-vl`, `vl:`, `ocr` 등의 특수 키워드가 발견될 때 일관되게 `Vision` 타입으로 감지되도록 구현합니다.
- `embedding` 모델은 `m.family == 'bert'`이거나 이름에 `embedding`이 탑재된 케이스를 감지해 분류합니다.

## [REVIEW_LOG]
* **검토자**: Reviewer Persona (Devil's Advocate)
* **검토 의견**:
  - **Edge Case 1 (필터링과 체크박스 상태의 독립성 보장)**: 사용자가 특정 모델들을 체크해둔 채로 필터를 변경(예: 슬라이더 조절로 목록이 축소됨)했다가 다시 필터를 초기화했을 때, 기존에 체크해둔 상태가 유실되면 대형 배치 테스트 기동 시 엄청난 사용성 하자가 발생합니다. 따라서 **체크박스의 실제 선택 상태(State)는 내부 변수로 온전히 보존하되, 화면에 보이는 렌더링 결과만 필터에 맞게 지우고 보여주도록 완벽하게 상태 독립적으로 설계**해야 합니다.
  - **Edge Case 2 (전체 선택/해제의 가시 범위 한정)**: 사용자가 "gemma"로 필터를 먹인 후 "전체 선택"을 클릭했을 때, 필터링으로 보이지 않는 "deepseek-r1:8b"까지 화면 뒤에서 같이 체크되어 실행 버튼을 누르는 사고를 방지해야 합니다. 따라서 **"전체 선택" 버튼은 반드시 '현재 필터를 통과하여 화면에 가시적으로 보이는 체크박스들만' 타깃으로 처리**되도록 방어 로직을 작성해야 합니다.
  - **DaisyUI 디자인 정밀성**: range input의 경우 단계별 눈금(ticks)과 현재 눈금 값을 나타내는 뱃지(badge), 하단 라벨 텍스트의 정렬이 기기 반응형 레이아웃에 상관없이 일렬로 우아하게 부착되도록 마크업을 미려하게 다듬어야 합니다.
