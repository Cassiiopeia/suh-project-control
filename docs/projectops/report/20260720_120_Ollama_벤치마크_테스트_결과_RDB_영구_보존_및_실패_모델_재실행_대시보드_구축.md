# Ollama 벤치마크 테스트 결과 RDB(PostgreSQL) 영구 보존 및 실패 모델 재실행(Retry) 대시보드 구축 보고 (#120)

## 개요
Ollama Structured Output 테스트 페이지 내 다중 모델 벤치마크 테스트 결과의 휘발성을 원천 극복하기 위해 관계형 데이터베이스(PostgreSQL) 마스터/세부결과(1:N) 테이블 연동 및 영구 보존 자동화를 단행하고, 테스트 도중 OOM/네트워크 장애 등으로 일부 실패한 모델만 골라 기민하게 재가동할 수 있는 "실패 모델 재실행(Retry)" 및 "과거 이력 역추적" Lazy-Loading 아코디언 대시보드를 전면 구축하여 배포(v2.0.59 완료)를 마감하였습니다.

---

## 주요 구현 사항 및 사양

### 1. PostgreSQL 기반 관계형 스키마 설계 및 마이그레이션 (0003)
- **`benchmark_batch` (마스터)**: 실험 일시, 프롬프트 원본, 시스템 프롬프트, 온도, 포맷 모드 및 적용 JSON Schema 사양을 보존합니다.
- **`benchmark_result` (결과)**: 모델별 성공여부, 생성 JSON 원문/에러 로그, 총 지연, 로딩 지연, 추론 지연, 인풋/아웃풋 토큰수 및 생성 속도(tok/s)를 보존합니다.
- **`unique_batch_model` (복합 유니크 제약)**: 동일 모델의 중복 적재를 원천 방지하고 재시험 시 원활하게 레코드를 최신화(덮어쓰기) 하도록 `ON CONFLICT DO UPDATE` (UPSERT) 안전장치를 설정하였습니다.

### 2. 백엔드 CRUD REST API 4종 추가 및 보호막 적용
- **`POST /ollama/benchmark/batch`**: 마스터 정보 생성 및 `batch_id` 발급
- **`POST /ollama/benchmark/result`**: 모델이 루프를 한 칸 끝낼 때마다 실시간으로 지표 데이터를 UPSERT
- **`GET /ollama/benchmark/history`**: 최근 15개 벤치마킹 마스터 이력 역순 조회
- **`GET /ollama/benchmark/history/<batch_id>`**: 특정 배치 하위의 개별 모델 지표 및 JSON 응답 Lazy Loading 조회
- 모든 신규 API 엔드포인트는 Nginx 및 백엔드 미들웨어 단위에서 **`X-API-Key` 비인가 조작 방지 및 `@audited` 감사 로그** 보호막을 완벽 장착하였습니다.

### 3. 실패 모델 일괄 및 단일 재실행 (Retry) 기능
- 요약 테이블 내의 실패 배지 우측에 회전 새로고침 아이콘 형태의 단일 모델 재시도 버튼 및 배치 카드 상단에 "실패 모델만 일괄 재실행 (Retry Failed)" 조작 기어를 탑재하였습니다.
- 현재 화면의 에디터 영역이 임시 오염되거나 갱신되어도 오작동을 완전히 차단하기 위해, 각 카드 엘리먼트 내부에 원천 파라미터 컨텍스트(`dataset`)를 격리 캡슐화 바인딩 처리하여 재시도 요청을 설계 전송합니다.
- 재테스트 성공 즉시 프론트 UI(테이블 및 상세 결과 코드 블록)가 실시간 업데이트되며 백엔드 DB에도 UPSERT 쿼리가 자동 유발됩니다.

### 4. 과거 벤치마크 이력 복원 대시보드
- 페이지 하단에 과거 테스트 이력 영역을 구성하고 데이터베이스로부터 이력 목록을 동적으로 바인딩합니다.
- 아코디언을 펼치는 순간(On Expand) 하위 결과를 Lazy-Loading 방식으로 지연 패치하여, 실시간 때와 100% 동일한 정량 비교 테이블과 상세 응답 JSON 카드를 완벽하게 영구 복원합니다.
- 과거 이력에 실패한 모델이 남아 있다면, 복원된 테이블 내에서도 위의 재시도 흐름을 완벽히 연쇄 가동시킵니다.
- '이 조건으로 실험' 복원 버튼을 구성하여 과거에 수행했던 모든 프롬프트, 포맷 모드, 온도를 원클릭으로 에디터에 로드 복원해 줍니다.
