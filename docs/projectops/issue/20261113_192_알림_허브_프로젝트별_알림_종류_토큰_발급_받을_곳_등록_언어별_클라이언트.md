📝 현재 문제점
---

- 다른 프로젝트 서버에서 민감하거나 운영자가 바로 알아야 하는 사건(Claude 로그인 코드 발급, 의견 접수, 신고 접수 등)을 Discord로 받고 싶은데, 알림 하나 추가할 때마다 관제소 코드를 고치고 배포해야 한다.
  - 프로젝트 채널 종류(상태·에러·신고·배포·확인할일)와 이벤트 종류(`report`·`error`·`deploy`·`status`·`info`)가 코드 상수로 고정
  - 종류를 추가하면 모든 프로젝트에 같은 채널이 생김
- 프로젝트 이벤트 토큰을 서버 환경변수로 손수 넣고 재시작해야 한다.
- 알림 수단이 SUH 관제소 Discord 봇 하나로 고정되어, 팀이 자기 Discord 서버나 슬랙으로 받으려면 각 레포가 웹훅을 따로 만들어 코드에 넣게 된다 (웹훅 주소가 레포마다 흩어짐).
- 다른 레포에서 쓸 사용 안내 문서와 공통 클라이언트가 없다.

🛠️ 해결 방안 / 제안 기능
---

- 설계: `docs/superpowers/specs/2026-11-13-control-tower-notification-hub-design.md`
- 각 앱은 관제소에만 한 줄로 보내고, 어떤 알림이 있고 어디로 가는지는 관제소 관리 화면 한 곳에서 관리한다.
- 쌓인 개수 알림(새 의견 N건, 미처리 신고 N건)은 기존 확인할 일(attention v1)을 그대로 쓰고, 이번 작업은 "방금 일어난 일" 이벤트 알림을 대상으로 한다.

⚙️ 작업 내용
---

- 1단계: 관리 화면에서 프로젝트별 알림 종류 추가 > 그 프로젝트에만 Discord 채널 자동 생성, 이벤트 항목(fields) 지원, 이벤트 규격 문서, Claude 로그인 코드 발급·열람 알림 (코드·Gmail 주소 제외)
- 2단계: 관리 화면에서 프로젝트 이벤트 토큰 발급·교체·폐기 (해시 저장, 발급한 프로젝트는 DB 토큰만 인정)
- 3단계: Apprise(BSD-2) 소스를 레포에 복사(라이선스 표시 유지) > 알림 종류별 추가 받을 곳 등록(팀 Discord 웹훅, 슬랙, 이메일 등, 암호화 저장) > 관제소의 모든 프로젝트 알림에 적용
- 4단계: Java·Python 서버용 클라이언트 (`clients/`), PyPI·Maven Central 배포
