📝 현재 문제점
---

- 감사로그가 팰월드 페이지의 텍스트 로그 뷰어 탭 하나에 얹혀 있어 전용 관리 화면이 없다.
- 화면에 카테고리(PALWORLD/TTS)가 표시되지 않아 `SERVER_START`가 어느 서비스의 동작인지 알 수 없다.
- TTS 엔진 정보 등 detail을 기록은 하지만 표시 로직이 일부 키만 읽어 화면에서 유실된다.
- `actor_ip`에 X-Forwarded-For 체인 전체(클라이언트 + Cloudflare + 내부 IP)가 통째로 저장·표시되어 실제 실행 IP를 한눈에 알 수 없다. (라우터마다 IP 추출 로직도 달라 표기가 제각각)
- 감사 기록이 라우터별 수동 호출이라 누락이 존재한다: 모델 관리(삭제/다운로드/취소)는 감사 기록이 전혀 없고, 실패한 제어 시도도 기록되지 않는다.
- 새 관리 엔드포인트를 추가할 때 감사 기록을 잊지 않게 하는 공통 장치와 문서화가 없다.

관련 파일:
- `suh-ai-server/flask/service/audit_service.py`
- `suh-ai-server/flask/router/palworld_router.py`, `router/tts_router.py`, `router/model_router.py`
- `suh-ai-server/flask/static/js/log-viewer.js`, `static/js/palworld.js`
- `suh-ai-server/flask/templates/admin/base.html`
- `suh-ai-server/flask/migrations/0001__create_audit_log.sql`

🛠️ 해결 방안 / 제안 기능
---

- 공통 감사 기록 데코레이터 도입: 라우트에 선언만 하면 클라이언트 IP, 프록시 체인, User-Agent 자동 수집, 응답 상태 기반 성공/실패 자동 판정, 실패 시도도 기록.
- DB 마이그레이션: `client_ip`, `proxy_chain`, `user_agent`, `success` 컬럼 추가 및 기존 데이터 백필 (기존 `actor_ip` 원본은 보존).
- 전용 감사로그 페이지 신설: 관리자 왼쪽 네비게이션에 "감사로그" 탭 추가, 구조화 테이블(KST 시간, 카테고리 뱃지, 행위 한국어 라벨, 실행 IP, 성공/실패, 상세 펼치기)과 필터(카테고리/행위/성공여부/검색) 제공.
- 구조화 조회 API 신설 및 기존 팰월드 로그 뷰어의 감사 탭은 전용 페이지 링크로 대체.
- 감사 커버리지 보강: MODEL 카테고리(모델 삭제/다운로드/다운로드 취소) 추가, TTS 엔진 정보 표시.
- 에이전트 가드레일: `suh-ai-server/flask/CLAUDE.md` 신설로 관리 엔드포인트 추가 시 감사 데코레이터 적용 규칙과 절차를 명문화.
