📝 현재 문제점
---

- 현재 `bin/` 디렉토리에는 PostgreSQL 백업 스크립트(`backup_postgres.sh`)만 존재하고 MongoDB용 백업 스크립트가 없다.
- 운영 중인 시놀로지 NAS의 MongoDB(romrom DB)가 랜섬웨어 공격으로 데이터가 전체 삭제되는 사고가 발생했다 (2026-05-01).
- PostgreSQL은 매일 03:00 자동 백업이 동작하는데 MongoDB는 백업 정책이 전무한 상태였음.
- 동일한 사고 재발 시 데이터 복구 수단이 없다.

🛠️ 해결 방안 / 제안 기능
---

`backup_postgres.sh`와 동일한 구조의 `backup_mongo.sh`를 `bin/`에 추가한다.

**스크립트 사양**
- 경로: `bin/backup_mongo.sh`
- 사용법: `./backup_mongo.sh <DB명> [백업경로] [보관일수]`
- 기본 백업 경로: `/volume1/projects/backup/mongo/${DB명}/`
- 기본 보관 기간: 30일
- 백업 형식: `mongodump --archive --gzip` (단일 압축 아카이브 파일)
- 파일명 패턴: `${DB명}_${YYYYMMDD_HHMMSS}.archive.gz`

**기능**
- `config/database.yml`의 `mongo:` 섹션에서 `username`, `password`, `container_name`, `auth_db` 자동 로드
- Docker 컨테이너 실행 상태 확인
- 디스크 여유 공간 검증 (최소 10GB)
- 백업 파일 무결성 검증 (gzip 헤더 + 최소 크기)
- 일반 로그 / 에러 로그 분리 저장
- 로그 자동 로테이션 (일반 10MB, 에러 5MB)
- 보관 기간 초과한 오래된 백업 자동 삭제

**`config/database.yml` 변경**
- `mongo` 섹션이 옛 자격증명(`admin/admin`)으로 남아 있어 함께 업데이트 필요
- 신규 자격증명: `kimchi/********` (admin DB 인증)
