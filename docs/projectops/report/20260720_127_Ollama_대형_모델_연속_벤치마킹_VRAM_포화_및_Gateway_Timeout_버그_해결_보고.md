# [버그] Ollama 대형 모델 연속 벤치마킹 시 VRAM 포화(OOM) 및 Gateway Timeout (Unexpected token '<') 에러 해결 보고 (#127)

## 개요
다중 모델 구조화 출력 벤치마크 테스트 도중, 대형 모델(7.8B, 8B 등)을 거칠 때 모델들이 줄줄이 `실패`하며 `Unexpected token '<', "<!DOCTYPE "... is not valid JSON` 에러를 뿜고 시스템이 일시 정지(Hang)되는 결함의 원인을 시스템 차원에서 정밀 진단하고, 자동 메모리 비우기 정책(Auto Unload) 기어를 연쇄 연동하여 결함을 원천 해결하였습니다.

---

## 버그 원인 규명 및 해결 내역

### 1. 원인 규명 (VRAM 포화 및 Timeout 병목)
- **메모리 잔재 축적**: Ollama의 기본 정책상 이전에 추론을 마친 대형 모델들이 VRAM에 계속 상주(`keep_alive` 기본 5분)하면서 GPU 메모리 한도를 초과하는 OOM 현상이 연속 유발되었습니다.
- **연산 교착(System Hang)**: GPU VRAM이 부족해지자 느린 윈도우 시스템 일반 RAM으로의 강제 스왑 페이징이 일어나며 극심한 병목 상태가 되었고, 추론 처리 지연 시간이 Nginx/Waitress 대기 시간 한도인 60초를 가볍게 돌파하였습니다.
- **HTML 에러 반환**: 결국 60초 타임아웃이 발생하여 504 Gateway Timeout HTML 페이지를 반환함에 따라 프론트엔드가 JSON 파싱 실패 에러를 뿜었던 것입니다.

### 2. 정교한 버그 해결 및 보완 조치
- **[자동 VRAM 청소 정책 기어 연계]**: Ollama 테스트 요청 구성 상단에 **"자동 VRAM 청소 정책 (Auto Unload)" 토글 스위치(기본값: ON)**를 이식하였습니다. 이 토글 활성화 시, 개별 모델의 테스트 추론 및 RDB 저장이 완결되는 즉시 백엔드로 Unload 신호를 전송합니다.
- **[공식 API 전환 가드]**: 임시 메시지 전송 방식의 기존 `/api/chat` 언로드 방안이 일부 윈도우 런타임 환경에서 파라미터 규격(messages 누락 등) 에러로 누수가 발생하던 문제를 타파하기 위해, 공식 소멸 표준인 **`/api/generate` 에 비어있는 `prompt: ""` 및 `keep_alive: 0`을 전송하도록 전수 보정 개편**하여 윈도우 실서비스에서도 100% 무결하게 메모리가 반환됨을 완전 보증합니다.
- **[NSSM SYSTEM 계정 로그 수집 가드]**: 윈도우즈 서비스 계정이 격리되어 사용자명이 `SYSTEM`으로 고정 수집됨에 따라 `C:\Users\chan4\...` 경로를 추적하지 못해 로그가 `없음`으로 표출되던 문제를 타파하기 위해, **`C:\Users\` 디렉토리 하위를 전수 동적 와일드카드 스캔하여 실시간 `server.log` 물리 절대경로를 자율적으로 포착해내는 고도화 수집기를 탑재**하고 인코딩 cp949 크래시 방어 가드를 적용하였습니다.

## 최종 검증 및 배포 완결 지표
- **테스트 무결성**: 연계 후 전체 299개의 백엔드 통합/단위 시스템 테스트 슈트(`pytest`)를 수행하여 **299 Passed (100% 무결 통과)** 상태를 다시 확보하였습니다.
- **자동 배포 출시**: 배포 PR **#130**을 통해 무결한 자동 병합 검증을 마치고 **v2.0.66** 버전으로 실서버 프로덕션 출시를 완전 마무리 지었습니다.
