# REQUIREMENT

## [PROBLEM]
현재 고도화된 Ollama Structured Output 테스트 페이지는 여러 모델을 순차적으로 벤치마킹하여 멋진 요약 비교 테이블과 상세 응답 카드를 제공하고 있으나, 다음과 같은 한계가 존재합니다.
1. **정량/정성 벤치마크 데이터의 고립**: 테스트를 돌린 훌륭한 요약 지표와 각 모델들의 세부적인 JSON 구조화 출력 응답들을 복사해 가거나 다른 대형 AI(Claude, GPT 등)에 프롬프트로 전달하여 심층 분석을 받기가 어렵습니다.
2. **가이드라인의 영속성 부재**: API Key 헤더를 자동 병합해 주는 `apiFetch` 사용 규칙과 "앞으로 모든 소스 코드 수정 및 개선 작업은 반드시 `develop` 브랜치에서 진행한다"는 안전 가이드라인이 명문화되어 있지 않아, 추후 협업이나 추가 개발 시 실수로 오염되거나 충돌을 유발할 여지가 있습니다.

## [REQUIREMENT]
1. **벤치마크 결과 내보내기 (Export Report) 기능 도입**
   - **위치**: 동적으로 생성되는 각 '배치 테스트 #X' 컨테이너의 헤더 우측 상단 영역에 "보고서 내보내기" 버튼을 추가합니다.
   - **기능**: 버튼 클릭 시, 해당 배치 세션의 모든 정량적 데이터(모델별 응답 시간, 로드 지연, 추론 속도, 토큰 수, 스키마 준수 여부 등)와 각 모델이 출력한 정성적 구조화 JSON 원문 데이터들을 조합한 **'AI 분석 및 사람 인지 최적화 마크다운(.md) 보고서'**를 자동 생성합니다.
   - **제공 방식**: 
     - **클립보드 복사**: 원버튼 클릭으로 마크다운 텍스트가 클립보드에 복사되어 다른 AI 프롬프트 창이나 메신저에 바로 붙여넣기 할 수 있게 합니다.
     - **파일 다운로드**: 브라우저의 가상 `<a>` 링크 다운로드 기법을 활용해 `ollama_benchmark_batch_#X.md` 파일로 깔끔하게 물리 다운로드할 수 있게 보장합니다.
2. **개발 및 운영 가이드라인 명문화 (`CLAUDE.md` 보완)**
   - `suh-ai-server/flask/CLAUDE.md` 가이드라인 문서 최하단에 다음 두 수칙을 강력하게 명문화합니다.
     - **프론트엔드 API 호출**: 비동기 API 요청 시 네이티브 `fetch`가 아닌, 자동 API-KEY 인증 및 `X-API-Key` 헤더 병합이 포함된 공통 `apiFetch` 래퍼 함수를 의무적으로 사용한다.
     - **브랜치 운영 규칙**: 모든 코드 수정, 핫픽스, 리팩토링 및 기능 고도화 작업은 반드시 `develop` 브랜치 위에서 온전히 시작하고 수립한다.

## [ASSUMPTIONS]
- 생성되는 마크다운 보고서에는 테이블 마크다운 양식과 코드 펜스(` ```json `)가 완벽하게 호환되어야 다른 AI 챗봇이 정교하게 파싱 및 인지할 수 있습니다.
- 클라이언트 사이드 단독으로 다운로드 및 클립보드 복사(navigator.clipboard API 또는 textarea 폴백)가 완벽하게 구동 가능하다고 가정합니다.

## [REVIEW_LOG]
* **검토자**: Reviewer Persona
* **검토 의견**:
  - **Critical Edge Case 1 (클립보드 복사 보안 컨텍스트)**: `navigator.clipboard.writeText` API는 보안 컨텍스트(HTTPS 또는 localhost) 환경에서만 정상 작동합니다. 비보안 HTTP IP 환경이나 일부 구형 기기 브라우저에서 복사 실패 시 예외를 포착(catch)하여 "자동 다운로드 파일로 대체 제공"하거나 "텍스트 강제 셀렉션 복사 폴백(Fallback)" 구조를 자바스크립트에 안정적으로 결합시켜야 신뢰성을 보장할 수 있습니다.
  - **보고서 가독성**: 마크다운 내에 각 모델이 생성해 낸 JSON 구조화 결과물들을 보여줄 때, 원시 한 줄 텍스트가 아닌 보기 좋게 들여쓰기 포맷팅(`JSON.stringify(..., null, 2)`)된 정돈된 상태로 가공 주입해야 AI가 분석 효율을 극대화할 수 있습니다.
